## Concepts learned

### PA table
Measured lookup chipsetting + gain-mode → real output at antenna; external PA gain is nonlinear/saturating.
Example: Meshnology W12 (GC1109 sub-G PA + RFX2402E 2.4G PA) caps chip at 4 dBm (GC1109 saturates at 3–4 dBm input).

### RF-switch mapping
GPIO choreography routing RX (ant→LNA→chip), TX (chip→PA→ant), band select (F33 dual U.FL).
In MeshCore: `rfswitch` table per variant `target.cpp`. Wrong timing = deaf radio or dead PA (TX into open circuit).

### SIMO
Chip DC-DC mode needing external inductor (both NiceRF variants, pins 14/16 LXA/LXB).
RX current 11→6.5 mA (40% cut).
**ERRATUM**: must re-apply after every `SetLoraModulationParams`/`SetRxPath` or silently reverts; carlhodder pushing fix to RadioLib.

### Patch RAM
LR2021 (like LR11x0) needs boot-time patches uploaded to chip RAM for features/silicon-bug workarounds.

## Addendum 2026-09-04: fkallay1's F33-2G4 measurements (PR #2739 comment, Aug-20)

Source: https://github.com/meshcore-dev/MeshCore/pull/2739 (fkallay1, XIAO nRF52840 + NiceRF LoRa2021F33-2G4, 18-pin dual-band). F33-specific; none of it applies to our plain modules — all of it applies to future F33 ground stations:

- Front-end DIOs DO need programming on the F33: DIO5-8 are LR2021 DIOs wired to the on-module front-end. setRfSwitchTable() writes the mode mask into the CHIP (not MCU GPIOs). Datasheet note: 2.4GHz LNA (DIO5) must sit HIGH (Bypass OFF) — LOW costs 12dB sensitivity. Sub-GHz PA enable = DIO6, active during TX_LF; not in the datasheet, comes from NiceRF demo code (LoRa/Core/Src/lr2021.c; DIO6 sub-GHz, DIO5/DIO7/DIO8 for 2.4G) — confirmed by NiceRF support. Without it: TX at bare chip power.
- TRAP: LR2021::setRfSwitchTable() indexes config by table COLUMN, not DIO number — pin array must be dense and ordered from DIO5. Listing DIO6 alone writes a zero config; PA stays off anyway.
- F33 TCXO: 3.3V (LR20XX_SYSTEM_TCXO_CTRL_3_3V in NiceRF demo; begin() accepts and prints 3.30V, no fallback). Wrong TCXO config returns exactly -706/-707 — which is why upstream dev LR2021 retries begin() with 0.0V on those codes. (Our plain module: crystal-only, tcxoVoltage=0 CORRECT — our historical -707 was the Arduino SPI driver, proven by EspIdfHal fixing RX with TCXO settings unchanged, field-validated.)
- PA dial: stock RadioLib PA table's lowest step ≈ +19dBm at antenna on F33; LORA_TX_POWER=22 ≈ +30dBm = datasheet max for 868/915 (1W, <800mA @5V). The "2W" headline is 433/470 only (33dBm — the F33 in the part number). fkallay1 remapped the dial so numbers mean dBm at module output — keeps `set tx` consistent with other high-power MeshCore boards. Above most 868 sub-band limits.
- Their plan (coordinate, don't duplicate): board-independent NiceRF_LoRa2021F33 support header in src/helpers/radiolib/ (RF switch table + remapped PA table + PRAM patch loader + boot report) + XIAO nRF52840 variant. Our ESP32-C3 can include it unchanged.
- Stale-SPI race (bogus RX length from status stream) reported by them upstream: RadioLib issue with reproduction — same code path our EspIdfHal works around.
