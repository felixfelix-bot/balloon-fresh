### PRBS-15 (Already in Place Before Measurement)

PRBS-15 was ported to E80 before the measurement (commits `b761022` through `17a6417`):
- 15-bit Galois LFSR, polynomial x^15 + x^14 + x^13
- Seed: `(seq ^ 0x5A5A) | 1`
- TX fills payload bytes 4..N with PRBS-15 (seed = sequence number)
- RX regenerates same stream, XORs, counts bit errors via `__builtin_popcount`
- 4-byte big-endian header (was 6-byte little-endian + length field before harmonization)
- Cross-platform verified: E80 and C3 produce identical PRBS-15 output

### What the E80 Firmware Did NOT Have Before Harmonization

Before the harmonization work (pre-commit `45a1be0`), the E80 firmware had:
- 6-byte little-endian header with 2-byte length field (now 4-byte big-endian, no length field)
- xorshift32 fill (now PRBS-15)
- No per-packet PKT output (now 23-field PKT on every received packet)
- No FW_HASH in boot banner (now stamped at build)
- No CRC-failed packet logging (now logged with RSSI)
- Sequence numbers reset on each START command (now persisted)
- No bit_err/bytes_bad fields (now populated by PRBS-15 verify)
- Console at 115200 baud (now 2,000,000)

## 4. Current Status Summary

### What Works

- E80-to-E80 PRBS-15 measurement: VERIFIED. 100/100 packets, 0 bit errors, 100% CRC, 23-field format confirmed.
- Both E80 boards flashed + responsive at 2M baud on /dev/ttyUSB3 (TX) and /dev/ttyUSB4 (RX).
- All 7 must-have harmonization items (M1-M7) implemented + verified.
- All 3 nice-to-have items (N1-N3) implemented.
- PRBS-15 cross-platform verified (E80 and C3 produce identical streams).
- Measurement capture tool (`fw_harm_measurement.py`) + 33 unit tests working.

### What's Not Done Yet

- **C3 (ESP32-C3) boards:** NOT connected. No ESP32-C3 hardware available. C3 firmware is built and ready but cannot be tested without boards.
- **Cross-platform measurement (E80 TX → C3 RX):** Blocked on C3 hardware.
- **PRBS-9 hardware test mode:** Implemented but causes TX timeout (chip-level diagnostic mode incompatible with packet TX flow). Requires SWD reflash to recover.
- **GPS fields:** All zero in current measurements (no GPS on bench boards).
- **Known issue — seed aliasing:** PRBS-15 seed derivation `(seq ^ 0x5A5A) | 1` forces bit 0 to 1, so consecutive even/odd sequence numbers (e.g., 42 and 43) produce identical PRBS streams. This doesn't affect measurement validity (packets are still verified correctly) but means the PRBS pattern repeats every 2 packets for even/odd pairs. Worth noting for data analysis.

## 6. Quick Reference — How to Run a Measurement

```bash
# 1. Acquire board locks
BALLOON_TRACK=balloon-range-tests python3 ~/repos/balloon-fresh/tools/balloon-board-lock.py acquire both --purpose "measurement" --timeout 120

# 2. Set up E80 boards (at 2M baud)
# TX board (ttyUSB3): ROLE TX → ARM TX → START N=100 LEN=64 GAP=10000
# RX board (ttyUSB4): ROLE RX → PRBS ON

# 3. Run measurement capture
cd ~/repos/balloon-fresh
python3 tools/fw_harm_measurement.py --port /dev/ttyUSB4 --rig e80 --duration 60

# 4. Release locks
BALLOON_TRACK=balloon-range-tests python3 ~/repos/balloon-fresh/tools/balloon-board-lock.py release both
```
