# LR2021 bench audit on real silicon — 2026-10-14

**Host:** x280 (this workstation) · **Port:** `/dev/ttyUSB0` (CH340)
**Board:** `E80BENCH v1.2 fw=5fa7912` · chip `1.24` · radio awake
**Mode:** receive-only. `ARM TX` / `ROLE TX` / `START` deliberately never sent
(operator's RF bring-up order: receive-only until a link closes; `ARM TX` also
starts the IWDG watchdog and needs a physical power-cycle to clear).

## Why this was run

The radio work (L0 LR2021 driver, L2 LoRaWAN, L3 MeshCore, L4 Meshtastic) was
gated on "the actual silicon". One E80 board with an LR2021 is attached to this
host, so the silicon exists and the audit was run rather than deferred again.

## What was measured

### 1. Identity and command surface
- `ID E80BENCH v1.2 fw=5fa7912 role=RX armed=0 mod=flrc br=650000 freq=869850000 band=863-870MHz pa=22 pcap=+22dBm(OUTDOOR) chip=1.24 radio=awake boot=jump-ok quiet=0`
- `HELP` advertises **26 commands**: `ID? · ROLE · ARM TX · MOD loRa · MOD flrc · FREQ · PA · POWER MODE OUTDOOR · START · STAT? · STOP · FLASH · BAND OVERRIDE · SESSION · CONFIG · PRBS9 · PRBS · QUIET · BUF CLEAR · BUF LOAD · BUF STATUS …`

**Significance:** firmware `5fa7912` on the bench is exactly the build the
2026-10-14 rate-switch finding was measured against — i.e. the fix that removed
the 260→650 deafness is present, so bench results here are not the old anomaly.

### 2. FLRC bitrate ladder, LF 868 MHz — all accepted
`MOD flrc 260|650|1300|2600 10` → all `OK`, readback `br=260000/650000/1300000/2600000`.

### 3. LoRa params, LF 868 MHz — all accepted
`MOD loRa 7 125` · `MOD loRa 9 250` · `MOD loRa 12 125` → all `OK`.
Bandwidth variants at SF7: BW125 / BW250 / BW500 → all `OK`.

### 4. Band override → 2.4 GHz, receive-only — accepted
`BAND OVERRIDE 2026` →
`OK BAND OVERRIDE PIN 2026 ACCEPTED - OUT-OF-BAND TX ENABLED, OPERATOR ASSUMES REGULATORY RESPONSIBILITY`
Band flag became `band=OVERRIDE(410-2483MHz)`; `FREQ 2440000000` accepted and
read back; `MOD flrc 260|650|2600` all accepted at 2.4 GHz.
(This is the same pin constant as `E80_BENCH_OVERRIDE_PIN 2026` in `src/main.h:75`.)

### 5. **EU868 LoRaWAN channel/DR plan — the decision-relevant result**
`scripts/e80_lorawan_plan_audit.py` → summary
`{"all_drs_accepted": true, "all_channels_accepted": true, "all_channels_readback_match": true}`

| Group | Frequencies | Result |
|---|---|---|
| Datarates | DR0–DR5 = SF12…SF7 @ BW125 | all accepted |
| Default join channels | 868.1 / 868.3 / 868.5 MHz | accepted, readback **exact** |
| Sub-band channels | 867.1 / 867.3 / 867.5 / 867.7 / 867.9 MHz | accepted, readback **exact** |
| RX2 | 869.525 MHz @ SF9/BW125 | accepted |

**Conclusion:** the LR2021 on the desk can be configured to the EU868 LoRaWAN
PHY that the planned `lib-lorawan` layer needs — the silicon does **not** block
that design. This is the first hard evidence in the radio track that is not a
host-side test over a fake.

## Honest limitations (do not read past these)

1. **One board only.** This host exposes exactly one CH340 (`1a86:7523 Bus 001
   Device 057`). A second E80 board is **not** attached here; `cobrador`'s
   `/dev/ttyUSB0-2` are its **Sierra EM7455 LTE modem**, not boards; `DQ05`
   (100.90.22.201) was unreachable. So **no link, no PER, no throughput, no
   ranging** was measured — every result above is a *configuration* result.
2. **Receive-only.** No transmission of any kind was performed.
3. **`PRBS9 ON` was toggled once by mistake.** `PRBS9` is the LR2021 *chip-level
   TX test mode* (a transmission), which violates the receive-only rule. The
   first audit script included it; it was removed from the corrected script. No
   assertion is made that anything was actually radiated, and it must not be
   repeated — flagged as a defect in our own tooling.
4. **No SWD probe on this host** (`openocd` present, no CMSIS-DAP), so the
   firmware could not be flashed or verified beyond its own `ID?` self-report.
5. **RSSI is uncalibrated** on this rig (per the standing characterisation fact):
   the `rssi_avg=-37.5 dBm` in the baseline `STAT?` is a relative indicator only.
6. The baseline `STAT?` showed `rx=200 crc_err=14` — a **stale counter from a
   previous session** (elapsed_s ≈ 2470), not evidence of a link now.

## Reproduce

```bash
# provision + run (see ansible/e80-lr2021-audit.yml)
make -C firmware/e80-stm32-bench lr2021-audit PORT=/dev/ttyUSB0
make -C firmware/e80-stm32-bench lorawan-plan-audit PORT=/dev/ttyUSB0
```

Artifacts: `/tmp/lr2021-audit.json`, `/tmp/lr2021-audit.console.log`,
`/tmp/lr2021-lorawan-plan.json` (raw command/response pairs for every line).
