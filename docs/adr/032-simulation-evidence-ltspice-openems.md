# ADR-032 — Simulation evidence for PCB design (LTspice + openEMS + stackup impedance)

- Status: Accepted
- Date: 2026-10-05
- Deciders: Felix (operator), manager
- Related: ADR-030 (zero-inference PCB pipeline, pending), ADR-031 (bring-up isolation, staged population), ADR-018 (multi-mode range characterization), ADR-009 (antenna strategy)

> Numbering note: 029 and 030 are reserved by open cards. This ADR is filed at 032.

## Context

ADR-030 makes board layout deterministic and zero-inference: a referee
(`kicad-cli pcb drc --json`) plus a committed rules file decide whether a board
is acceptable. That covers **geometry legality** (shorts, clearance, crossings).
It says nothing about **whether the circuit is electrically correct**.

The gap showed up when defining the 50 Ω RF feed: we had a pi network because
the stackup was never pinned, not because a pi network was required. A correctly
computed microstrip on a known stackup needs no tuning — but "correctly computed"
is a claim that must be backed by evidence, not asserted.

The operator asked whether simulation belongs in the quality gates or in an ADR.

## Decision

**Both, in this division:** the ADR defines the *evidence contract* (what must
exist and what it must show). A quality gate *enforces* that the evidence exists.
An ADR cannot block a card; a gate cannot explain a method. Adopting one without
the other gives either unenforced prose or an unexplained checkbox.

### Evidence required before a board may be ordered

**E1 — Electrical simulation (LTspice). Mandatory for every designed board.**
Frequency- and time-domain evidence for the lumped/electrical side:
- RF matching network response (impedance transformation over the band of interest),
- any filter/harmonic-suppression stage (insertion loss in-band, rejection at the
  interfering frequency — e.g. the 868 MHz 3rd harmonic at ~2604 MHz),
- supply integrity: TX-burst current transient per rail, decoupling impedance,
  and the rail droop at the worst-case current step,
- LNA/bias/RF-switch networks where present.

Requirements: the model is committed as a file (`*.asc` + any subcircuits) in the
repo alongside the board; the *netlist and the sweep/source setup* are committed,
not just a screenshot; and the report states the corner conditions simulated.

**E2 — Geometry/impedance computation. Mandatory for every controlled-impedance
or RF trace.**
- Trace geometry (width, gap, layer, reference plane) is computed against the
  *pinned* JLCPCB 4-layer stackup, with the layer table (εr, thickness) committed
  next to the calculation.
- Computed with a stackup impedance calculator, and independently in **openEMS**
  where a genuine EM answer is needed (matching network into the actual board
  geometry, coupler/pad parasitics, keep-out effects, antenna where in scope).
- The result to be recorded is the **resulting Z0 (Ω) and the computed component
  values**, plus the raw stackup inputs, so the calculation can be re-run.

**E3 — The honesty clause (mandatory in the report).**
Simulation is **nominal only**. εr tolerance, etch tolerance and component
tolerance mean a simulated S11/Z0 is not a guarantee. Every simulation report
must state this and name the tolerances it did *not* model. Simulation narrows
the search space; measurement decides.

**E4 — Simulation does not replace measurement; it sequences it.**
Required order: simulate → compute geometry → assemble → measure → tune only if
the measurement demands it. The tuning pads of ADR-031 D6 exist to close the
measured gap, not to pre-empt the calculation.

**E5 — What is NOT admissible as evidence.**
- A plot without the model that produced it.
- A model without its source/sweep setup (unreproducible).
- A "we checked it" statement in a card body.
- Any result generated by an LLM rather than by a solver (this ADR is about the
  circuit, not the router — ADR-030 governs the router).

### Enforcement

A `sim_evidence` check is defined with these semantics: for a card whose board
carries RF or a controlled-impedance trace, the card must cite (a) a committed
LTspice model + its report, and (b) a committed geometry/impedance calculation
against the pinned stackup. Missing evidence ⇒ the board card cannot reach
`order-ready`. Implementation is carded (see Consequences); until it exists the
check is performed manually in review and recorded on the card.

## Consequences

- Every RF board now carries a solver model and a stackup calculation in the repo.
  This is the cost; the benefit is that the pi network can stay at fixed values
  and an assembled board needs no hand fitting.
- The `sim_evidence` gate must be implemented and registered (a `pcb` tier in the
  gate config) rather than assumed — carded separately, because a gate named in
  config but missing in the checker is worse than no gate.
- A wrong land pattern or a wrong matching network is now caught before the turn,
  which is the whole point: the failure we are insuring against costs a board
  turn (~2 weeks), not a simulation run (~minutes, $0.00 inference).

## Rejected alternatives

- **Gate only, no ADR** — no one could tell *why* the evidence is required or
  what "sufficient" means, and the gate becomes a ritual.
- **ADR only, no gate** — the requirement quietly stops being met, as the
  unpinned-stackup pi network already demonstrated.
- **Skip LTspice, tune on the bench** — rejects the premise: tuning needs the
  board, the board needs a turn, a turn costs two weeks. Simulation is the
  cheapest place to be wrong.
- **Trust LTspice for geometry** — it is a lumped-element solver; it cannot
  produce a microstrip Z0 or an antenna pattern. Geometry needs a field solver.
