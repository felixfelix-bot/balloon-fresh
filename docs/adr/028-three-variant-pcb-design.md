## Context

The balloon project has accumulated 33 board variants generated by Python
scripts (`full_pipeline.py`) without any schematic (.kicad_sch) files. No ERC
has ever been run. The script-generated boards hit a routing wall: 2-layer
boards cannot converge on 0/0 DRC because power nets (GND, 3V3, VCAP) account
for 50% of unconnected pads, and auto-routing cannot find clear paths through
signal pads.

Three MCU targets are in play:

1. **ESP32-C3** — Current testing platform. ESP32-C3 Super Mini dev boards
   are small, light, and cheap. Firmware builds and runs on this target
   today (22K LOC, 119 tests passing). Used for breadboard prototyping
   and pico balloon flight tests.

2. **ESP32-S3** — Future migration target. More GPIO, more RAM, faster
   CPU. The three TollGate boards in inventory are S3-based. Firmware
   already has S3 build targets. Migration requires pin remapping.

3. **ESP32-C3 + RP2040** — Dual-MCU architecture (per ADR-026). C3 handles
   WiFi/Bluetooth, Nostr, TollGate application logic. RP2040 handles
   LR2021 radio SPI, real-time radio tasks, and interrupt handling.
   Inter-MCU communication via UART or SPI.

The firmware was found to target ESP32-S3 while the boards were generated
for ESP32-C3 — an MCU mismatch that went undetected because no schematic
existed to catch it via ERC.

## Decision

Design three PCB variants, each starting with a proper KiCad schematic
(.kicad_sch) before any board layout:

1. **Balloon-C3** — ESP32-C3 single-MCU board (immediate testing)
2. **Balloon-S3** — ESP32-S3 single-MCU board (future production)
3. **Balloon-Dual** — ESP32-C3 + RP2040 dual-MCU board (advanced radio architecture)

All three share the same peripheral set:
- LR2021F33 radio (SPI)
- MAX-M10S GPS (UART)
- TPS7A02 LDO + supercap + solar power chain
- 2x U.FL antenna connectors (sub-GHz + 2.4GHz)
- Optional FEM (SKY66112 or equivalent)
- ADC voltage divider for supercap monitoring

### Design Process (MANDATORY)

For each variant:

1. Draw schematic (.kicad_sch) with correct symbols and wire connections
2. Run ERC — fix ALL errors before proceeding
3. Assign footprints
4. Create board (.kicad_pcb) — 4-layer stackup (F.Cu / GND / 3V3 / B.Cu)
5. Place components
6. Auto-route signals (FreeRouting) — GND and 3V3 handled by internal planes
7. Run DRC — target 0 violations / 0 unconnected
8. Export gerbers
9. JLCPCB order

### Tooling

- KiCad 9 + kicad-cli for headless DRC and gerber export
- python3.14 + pcbnew API for board creation and programmatic operations
- FreeRouting for auto-routing signal nets
- kimi-k3:cloud (worker-layout profile) for ALL schematic and board layout
  work — glm-5.2 proven unable to do spatial reasoning (80+ shorts per
  routing attempt)

## Invariants

1. Every board variant MUST have a schematic file (.kicad_sch) that passes
   ERC before board layout begins.
2. Pin assignments MUST be verified against the firmware's Kconfig/menuconfig
   for the target MCU.
3. 4-layer stackup (F.Cu / In1.Cu=GND / In2.Cu=3V3 / B.Cu) is the default
   for all custom PCBs. 2-layer only for dev-board breakout boards.
4. All board/schematic files MUST be committed to git and pushed before
   ordering from JLCPCB.
5. kimi-k3:cloud (worker-layout) is the ONLY model that touches schematic
   and PCB spatial work.

## Consequences

### Positive

- Proper schematics catch pin assignment errors before fabrication (the MCU
  mismatch would have been caught by ERC)
- 4-layer stackup eliminates power routing problems (GND + 3V3 planes)
- Three variants cover the full design space: current testing (C3), future
  production (S3), advanced architecture (C3+RP2040)
- Shared peripheral set means schematic sheets can be reused across variants
- Schematic-first approach produces maintainable, reviewable designs

### Costs

- Three board designs to maintain (vs one)
- 4-layer boards cost ~$8/5 vs ~$2/5 for 2-layer ($6 premium, negligible)
- Schematic drawing is upfront time investment (~2-4 hours per variant)
- C3+RP2040 variant has additional complexity (inter-MCU bus, dual firmware)

## Notes

- The 2-layer V2-ADC board (v2_adc_fixed2.kicad_pcb) remains as the best
  script-generated board (0 violations, 16 unconnected power nets). It is
  orderable for pad fit / component placement validation. The 16 unconnected
  power pads can be jumper-wired after assembly.
- Previous board generation used Python scripts without schematics. This
  produced 33 variants with inconsistent pin assignments. The schematic-first
  approach replaces this entirely.
- ADR-026 (dual-MCU radio architecture) defines the rationale for the C3+RP2040
  variant. This ADR covers the physical PCB implementation of that architecture.
