## 0. The question this record answers

The operator asked, verbatim intent:

> *"let's do the NTC thing as well. Please make sure that we have an ADR for this."*

"The NTC thing" is the LR2021's **on-chip XTAL temperature-compensation loop**: the silicon
contains the compensation engine; it only needs an **external NTC thermistor + bias resistor**
populated at the crystal and wired to two chip pins. The MeshCore community discussed exactly this
mechanism and **could not use it because their RadioLib lacked support**
(`docs/analysis/meshcore-lr2021-drift.md` §7, `gh api search/code` → `total_count=0` for
`SetTempCompCfg`); our vendored driver is the same upstream project, so the same gap applies and
must be stated (§1.2). This record adopts the route as a **hardware provision**, states the
constraint that governs the whole design (§2 D2), fixes the siting rule (§2 D3), and names the one
thing that currently blocks it on our own modules (§2 D6).

## 1. What is verified, and where (every register, pin and figure quoted)

### 1.1 The chip commands and the pins — Semtech datasheet

Verified on this host with `pdftotext -layout` of
`docs/lr2021-research/semtech-official/LR2021_LR2022_LR2012_Datasheet_v2.2.pdf` (Rev 2.2):

- **§6.12.1 `SetTempCompCfg`** — `Table 6-69: SetTempCompCfg Command`, command bytes `0x01 0x32`
  (opcode **`0x0132`**), p. 133. Quoted: *"The SetTempCompCfg command configures the heating
  compensation block in Tx if an XTAL 32 MHz is used."* Fields: `ntc` (*"1: Enables NTC / 0:
  Disables NTC"*) and `comp_mode(1:0)` (0x0 Disabled, 0x1 Relative, 0x2 Absolute, 0x3 RFU).
  **And the governing constraint, in the same section, quoted verbatim: *"If a TCXO was configured
  this command fails."***
- **§6.12.2 `SetNtcParams`** — `Table 6-70: SetNtcParams Command`, `0x01 0x33` (opcode **`0x0133`**),
  same page. Quoted: *"The SetNtcParams command enters the NTC parameter to be used during heating
  compensation."* Fields: `ntc_r_ratio` (*"Defines the ratio between the resistor bias value and
  the NTC resistor value at 25 °C, on 10 bits with 9 fractional bits (10,9)"*), `ntc_beta`
  (*"NTC temperature in 2 Kelvin/lsb"*), `delay` (*"First order time delay coefficient"*).
- **§6.5.2 `GetTemp`** — `Table 6-33: GetTemp Response`, opcode **`0x0125`**, p. 117. `Source(1:0)`:
  *"0x00: Built-in junction temperature Vbe · 0x01: Built-in junction temperature close to XOSC ·
  **0x02: NTC** · 0x03: RFU"*. `Format` 1 = °C (*"Actual temperature = Temp/32"*). The same table
  carries the second half of the mutual exclusion, quoted: *"Note: If a TCXO is currently being
  used, this command fails if the NTC is used as source."* For the NTC source the datasheet gives
  the conversion the parameters must satisfy: *"RRatio = RNTC/RNTC_25 = RBiasRatio *
  (Raw/8192)/(1.0 - (Raw/8192))"* and *"T = Beta/(ln(RRatio) + Beta/298.15) - 273.15 … Where
  RBiasRatio, Beta are values set by the SetNtcParams command."* (It refers the reader to
  **AN1200.106** for details — **not committed in this repo**: `TODO(unverified)`.)
- **§1.9.2 "32MHz Crystal"** (p. 32–33, `Figure 1-15: NTC Connection`). Quoted: *"The optional XTAL
  temperature compensation mechanism measures the XTAL temperature change and compensates on chip
  for the induced frequency shift. When the temperature compensation mechanism is used, the VTCXO
  pin can be used to power an external temperature sensor (R and NTC) monitoring the XTAL
  temperature. The NTC output is then fed into the chip via pin NTC and measured by an increase in
  ADC. The resulting temperature information is used by the chip to automatically compensate, to
  some extent, the frequency shift due to XTAL heating."*
- **The two chip pins** — `Table 2-1: Pin-out Description (Sheet 1 of 2)`, p. 34. Quoted: **pin 3 =
  `NTC`, "Negative Temperature Coefficient (NTC) resistor connection"**; **pin 6 = `VTCXO/VNTC`,
  "External TCXO supply voltage (REG_TCXO) / NTC supply"**. So the loop needs **both**: the divider
  is *powered* from VTCXO/VNTC (pin 6) and its midpoint is *sensed* back on NTC (pin 3).
- The datasheet reference schematic repeats the two pin names (*"NTC 3"*, *"VTCXO/VNTC 6"*) and adds
  the no-NTC disposition: *"NTC pin if no NTC Resistor: Leave unconnected"*.
- **Ratings that bound the provision** (DS 2.2, p. 38): `Table 3-1` `Tmr` = **−55…125 °C**;
  `Table 3-2` `Top` (ambient) = **−40…85 °C**, `Tmaxj` = **105 °C**. The **−60 °C** flight design
  case is below both minima — the loop does not change that (see §5 open items).
- **The rail that biases the divider**: `Table 3-25: TCXO Regulator Specifications (LR20xx)`
  (p. 70) — `ILTCXO` *"Load current for TCXO regulator"*, **typ 1.5 mA / max 4 mA**. The NTC bias
  current is a small fraction of that, which is why the provision is a microwatt-scale load
  (ADR-042 Addendum A2 makes the same point and this record does not restate its arithmetic).

- **`RADIOLIB_LR2021_CMD_GET_TEMP` = `0x0125` — confirmed** (line 32).
- **`RADIOLIB_LR2021_CMD_SET_XOSC_CP_TRIM` = `0x0131` — confirmed** (line 55).

  A recursive `grep -rni "ntc"` over

  wrappers do not exist. Marking the pair `0x0132`/`0x0133` as "supported" would be **false** for

  LR2021.cpp:987               float LR2021::getTemperature(...)   // calls getTemp(), returns 0 on error

### 1.3 The two modules' 18-pin tables — the module-level question

- **Bare NiceRF LoRa2021** (ours, 4×) — `docs/assets/lr2021/LoRa2021-Module-Datasheet-V1.3.pdf` §7
  "Pin definition" enumerates **all 18 pads**: `1 VCC · 2,8,11,12,18 GND · 3 MISO · 4 MOSI ·
  5 SCK · 6 NSS · 7 BUSY · 9 ANT · 10 2.4/S_ANTA · 13 VTCXO · 14 RST · 15 DIO9 · 16 DIO8 ·
  17 DIO7`. Pad 13 is listed as `VTCXO`, `O`, *"Can provide power for an external TCXO."* **There
  is no `NTC` pad, no `XTA`, and no `XTB`.** The module therefore breaks out the chip's
  **VTCXO/VNTC supply** (chip pin 6) but **not the chip's NTC sense input** (chip pin 3).
- **F33-2G4** — `docs/f33-module/LoRa2021F33-2G4-datasheet-v1.1.pdf` (Rev 1.1) §7 "Pin definition"
  enumerates **all 18 pins**: `1 VCC · 2,3,4,6,7,8,11 GND · 5 CE · 9 ANT · 10 ANT-2G4 · 12 SCK ·
  13 NSS · 14 BUSY · 15 MOSI · 16 MISO · 17 RESET · 18 IRQ`. **No VTCXO, no NTC, no XTA/XTB.** The
  same datasheet's first page states the module carries an *"Industrial-grade TCXO Crystal
  Oscillator 0.5PPM"*. So the F33's reference is compensated inside the part, and it has **no pin**
  for either the TCXO or the NTC path.
- The **SX1280** is a different chip (Semtech 2.4 GHz ranging transceiver, 52 MHz reference) and has
  **no LR2021 temperature-compensation facility at all**; it is not in scope for this route.

### 1.4 ADR-042 Addendum A2 already filed this fix — verified wording

`docs/adr/042-thermal-drift-strategy.md` **Addendum A2**, verified verbatim in-tree, already says:
*"Fitting a 100 K NTC on pin 3 closes the loop — one component (plus a series R to the VTCXO

## 2. Decision

### D1 — The NTC route is ADOPTED as the on-chip compensation mechanism for the crystal-configured LR2021, and the board provides for it

**Decision:** for a **crystal-configured** LR2021, the on-chip XTAL temperature-compensation loop is
the adopted compensation mechanism, and the board carries the provision it needs: **an NTC
thermistor footprint plus its series resistor to the VTCXO rail**, wired as §1.1/§1.4 describe
(NTC from the sense node to GND; series R from the VTCXO/VNTC rail to the sense node).

This is not a re-decision of ADR-042's ranking; it adopts A2's item as a **provision with a
land pattern**, so that a module which breaks out the pins can close the loop at **zero respin
cost** — there is **no v9 hub PCB yet**, so adding the land costs nothing today.

The provision is implemented in the v9 design-intent schematic's generator
(`tracker/hardware/schematics/flight_board/build_flight_sch.py`, `v9` target) and is regenerated
from it, so the tree stays reproducible (§4). **Nothing is ordered.**

### D2 — The mutual exclusion is explicit, and its consequence per radio

**Decision, stated plainly because it governs the whole design: the on-chip NTC temperature
compensation FAILS IF A TCXO WAS CONFIGURED.** TCXO compensation and NTC compensation are
**mutually exclusive on this chip**. Two independent datasheet statements say so (§1.1):
`SetTempCompCfg` — *"If a TCXO was configured this command fails"*; and the `GetTemp` NTC-source
note — *"If a TCXO is currently being used, this command fails if the NTC is used as source."*

**Consequence per radio:**

| Radio | Reference fitted | Compensation route | What the board does |
|---|---|---|---|
| **F33-2G4** | internal 0.5 ppm TCXO, **no VTCXO pin** (§1.3) | **TCXO path — already fitted** | **Nothing to do.** The TCXO is inside the part; the NTC path is unreachable *and* unnecessary (the chip's TCXO-configured state would fail NTC config anyway). |
| **bare NiceRF LoRa2021** | crystal, no TCXO, no NTC | **NTC path is the correct route** — *subject to the pin break-out blocker, D6* | The NTC + series-R provision (D1); **DNP** until D6 resolves (§4). |
| **SX1280** | its own 52 MHz reference | **neither** | Nothing. It is a different chip; the LR2021 facility does not apply. |

### D3 — The NTC must be thermally coupled to the radio reference and away from self-heating neighbours

**Decision (siting rule):** the NTC footprint is placed **thermally coupled to the radio's reference
(the XTAL), on the same thermal island as the module's crystal — not parked on the far side of the
board** — and it is **not sited where a self-heating neighbour dominates its reading** (explicitly:
**not adjacent to the F33's 2 W PA**, and **not adjacent to the hub converter** on a hub-side
variant).

**Reason, from the sources:** the loop's whole purpose is to measure **the crystal's** temperature
change — *"measures the XTAL temperature change and compensates on chip for the induced frequency
shift"*, and the sensor is *"an external temperature sensor (R and NTC) monitoring the XTAL
temperature"* (§1.1). A sensor separated from the crystal by FR4 measures the *board*, not the
crystal (ADR-042 Addendum A3 point 3 makes the same argument against a board heater). A sensor
dominated by a neighbour's dissipation measures the *neighbour*: the F33's PA is the single largest
heat source on the board (§D6 open item), and the hub converter is the hub variant's. Either way the
reading is biased away from the node that matters, and a biased sensor silently mis-compensates
rather than failing visibly.

### D4 — The `SetNtcParams` inputs must be characterised, not guessed

**Decision:** `ntc_r_ratio`, `ntc_beta` and `delay` (D1/§1.1, `SetNtcParams` `0x0133`) must be
**derived from the populated part and its bias resistor**, never defaulted to a plausible number.
The parameters that **must be filled in** are recorded here as an explicit list, all
**`TODO(unverified)`**:

- the NTC's **R25** (`RNTC_25`) and the **series/bias resistance** → they set `ntc_r_ratio`
  (`RBiasRatio`, the ratio of the resistor bias value to the NTC value at 25 °C, 10-bit with 9
  fractional bits) — **`TODO(unverified)`**;
- the NTC's **beta** (K) → sets `ntc_beta`, given as **2 K/lsb** by the datasheet — the beta
  coefficient is **`TODO(unverified)`**;
- the **first-order delay coefficient** — **`TODO(unverified)`**;
- the checked identity is the datasheet's own: `RRatio = RNTC/RNTC_25 = RBiasRatio *
  (Raw/8192)/(1 - Raw/8192)`, and `T = Beta/(ln(RRatio) + Beta/298.15) - 273.15` (§1.1).

A value copied from a forum ("assume 4250 K") is **not** a characterisation and must not be entered
as one. Where a working figure is needed to bring the loop up on a bench, it is entered **and
labelled as a bench placeholder in the firmware, not as the part's parameter**.

### D6 — THE NAMED BLOCKER: is the NTC input pin broken out on the owned bare NiceRF module?

**Decision (disposition):** the route is **adopted as a provision but BLOCKED as a build** on the
owned bare NiceRF LoRa2021, because on that module **the chip's NTC sense input (chip pin 3) has no
corresponding castellation**. The blocker is *named*, its evidence is *stated*, and the fallback is
*fixed* — it is not silently assumed away.

**Evidence now in hand (new in this record; changes the blocker from "unknown" to "evidence
indicates NOT broken out"):** §1.3 — the vendor's own Rev 1.3 **pin-definition table enumerates all
18 pads of the bare module** and the only oscillator-related pad is **13 = VTCXO**, described solely
as *"Can provide power for an external TCXO."* The chip's NTC pin (pin 3) is **not** among them;
module pad 3 is `MISO`. Corroborating in-repo statements: `docs/analysis/external-clock-and-ocxo.md`
(Part A row for the bare module: *"the module does **not** break out the chip's XTA/XTB clock inputs
on its 18 castellations"*, and *"Module pad 13 = VTCXO, but that is an **output**"*),
`docs/assets/lr2021/README.md` (pad 13 `VTCXO`, disposition **"NC (leave floating)"**), and
`docs/LR2021-LESSONS-2026-09.md` line 22 (the four owned plain modules are *"crystal, no TCXO, no
NTC (carlhodder deshielded to verify)"*).

**What would resolve it (the confirmation still owed):** the **module mechanical drawing** (the
vendor's own pin-out drawing, as opposed to the pin-definition *table*) **or a deshielded photo of
the bare module's castellations** — the same evidence ADR-042 Addendum A2 asks for and does not yet
have. Until that evidence exists, the finding above is strong but is **not** promoted to "proven
absent": **`TODO(unverified)`** remains on the module-level question, because a pin table can be an
abbreviation and a module revision can differ.

**Fallback if the pin is not available (fixed now, so it is not re-argued later):**
1. **Do not fit the NTC on a bare module** — the land stays, DNP (the honest state: a populated NTC
   with no sense path only draws bias current and corrects nothing).
2. Use the **compensated part where compensation is needed** — fly the **F33** (its internal TCXO is
   the ADR-042/ADR-056 rank-1 answer), or a **TCXO-bearing LR2021 module** if one is chosen; note
   that on the *bare* module pad 13 = VTCXO, so a module that *did* break out XTA (per §1.3, ours
   does not) could take an external TCXO.
3. Fall back to the **firmware `f(T)` pre-distortion** (ADR-042/ADR-056 rank 2) and the **GPS 1PPS
   discipline** (ADR-056 §D3) — both already decided elsewhere and not duplicated here.

**This blocker is the reason the schematic provision in §4 is marked DNP.**

## 3. Why this provision and not something else

Not a re-litigation: ADR-042 already rejected the board heater by arithmetic (§D1) and ADR-056 §D1
re-derived it in `P = G·ΔT` form, and ADR-043 rejected heating for cold qualification. This record
adds only the structural reason the NTC loop differs from the heater and is worth a land even while
blocked: the loop corrects **frequency**, not temperature; it needs **no continuous power** to fight
an ambient gradient and **no awake MCU** (the compensation runs inside the transceiver, ADR-042 A2);
and it is **one component plus a bias resistor**. Where the loop is *usable*, it is the cheapest
hardware answer after the TCXO itself. Where it is *not* (our bare module, until D6 resolves), the
land costs nothing and the fallbacks are already decided.

**Honest limit, carried from ADR-042 §A5 and not over-claimed here:** the datasheet's crystal
accuracy figure (`FRTOLHF` = ±10 ppm) is characterised **over −20…+70 °C** only
(`Table 3-24`, DS 2.2, p. 68). **Neither the NTC loop nor the TCXO gives a guaranteed ppm figure
outside that window**, and this record claims none; quantifying the residual at the −60 °C design
case is a measurement, not a datasheet read.

- **`TH_NTC1`** — `Device:Thermistor_NTC`, the NTC thermistor from the sense node to **GND**. Value
  **`TODO(unverified)`** (part, R25 and beta per D4).
- **Nets:** `VTCXO_VNTC` = {`U3` pad 13, `R_NTC1` pin 1} (the bias rail, sourced from the bare
  module's `VTCXO` pad — §1.3); `NTC_SENSE` = {`R_NTC1` pin 2, `TH_NTC1` pin 1} (the sense node that
  the chip's `NTC` pin would read); `TH_NTC1` pin 2 → `GND`.
- **Both parts are DNP**, with the reason recorded on the sheet and in the netlist note: **the
  sense node has no path back to the chip on the owned bare module** (D6), so the loop cannot be
  closed; the land exists so that a module which breaks the pin out closes it at zero respin cost.
- The generator's `V9_BARE_PINS` **pad 13 is renamed from the placeholder `PAD13_?` to `VTCXO`**,
  because the vendor pin table now names it (§1.3); `OPEN-5` is updated accordingly (pads 16/17 stay
  open). This is a *naming correction with a source*, not a connectivity change.

Gate deltas are reported on the card and are not asserted here as text; the numbers live in the
commit message and in the final report. The generators' determinism gate (byte-identical across two
runs) is re-run and must pass.

## 5. Open items

1. **The module pin break-out (THE blocker, D6).** Whether the chip's `NTC` pin (chip pin 3) is
   broken out on the owned bare NiceRF module. Evidence in hand says **no** (vendor pin table, all 18
   pads, §1.3); the confirmation owed is the **module mechanical drawing** or a **deshield photo**.
   `TODO(unverified)`.
2. **NTC part selection, including its cold rating.** The part must be chosen and its R25/beta read
   from its own datasheet (D4). The rating must be checked against the **−60 °C** flight design case
   with the same rigour the array work applied: **ADR-054 §4 records that every verified
   semiconductor there is rated −55 °C (diodes) or −40 °C (converters) against the −60 °C case**, and
   the LR2021 silicon itself is `Top` **−40…85 °C** / `Tmr` **−55…125 °C** (DS 2.2 Tables 3-1/3-2).
   An NTC whose only spec is a "−40 °C" commercial grade is **not** a −60 °C part; do not assume the
   thermistor is the one component exempt from the cold-rating gate.
3. **The `SetNtcParams` values** — `ntc_r_ratio`, `ntc_beta`, `delay` (D4). All `TODO(unverified)`
   until the part is characterised. **AN1200.106** (the datasheet's reference for the NTC maths) is
   **not committed in this repo** — obtain it before deriving the parameters.
4. **Whether the F33's PA self-heating perturbs a nearby NTC.** The F33's 2 W PA is the largest
   local heat source (D3); if an NTC is ever sited near an F33 (e.g. on a future combined board), the
   PA's duty cycle would dominate its reading. **Not measured; `TODO(unverified)`.** Today the
   provision sits on the *bare*-module side, which is why the siting rule (D3) names this case
   explicitly rather than leaving it to layout.
5. **Driver support.** The vendored RadioLib (pinned `f403b9c3`) has **no `SetTempCompCfg` /
   `SetNtcParams` wrapper and no `TEMP_SOURCE_NTC` constant** (§1.2). Until those exist (upstream or
   a local patch), the NTC loop cannot be enabled from firmware at all — this is a **firmware
   dependency**, not a hardware one.
6. **The `°C` read scale.** `getTemp()` divides by **320** where DS 2.2 says the °C format is
   `Temp/32` (§1.2). Resolve against hardware before trusting a temperature in either direction.

## 6. What this record does NOT decide

- It does not re-open the heater rejection (ADR-042 §D1, ADR-056 §D1) or the cold-qualification
  heating rejection (ADR-043).
- It does not decide the **runtime** compensation scheme, the **per-unit calibration curve**, or the
  **GPS 1PPS discipline** — those belong to the concurrent `adr/onboard-temp-compensation` record and
  ADR-056 §D3 (D5).
- It does not decide the **SX1280's** reference (a TCXO-bearing module is required if it flies as a
  time reference; that is ADR-056 §D2).
- It does not order anything, freeze a BOM, or authorise fabrication.
